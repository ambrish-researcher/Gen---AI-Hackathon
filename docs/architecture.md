# Architecture

React/TypeScript/Vite provides the Studio. Zustand holds streamed mission state and view preferences; TanStack Query fetches map, diagnostics and persistent records. React Three Fiber renders authoritative state with smoothed visual interpolation; it cannot mutate simulation positions. Repeated rack geometry uses an instanced mesh, adaptive low quality disables shadows/antialiasing, and pixel ratio is capped. FPS is measured from actual frame intervals, not a fixed decorative label. Cameras, replay and layout respect reduced-motion settings where applicable.

FastAPI owns a single mission. A background worker advances fixed 0.05-second simulation steps independently of rendering and inference. WebSocket snapshots stream at 10 Hz. UI mutations and worker ticks execute on the same event loop. Batch experiments run in a thread to avoid blocking mission stepping. This design targets one local operator, not multiple independent users.

`agents/interpreter.py` extracts grounded station references and builds Pydantic-validated actions. It rejects unrecognized wording and capabilities. `planning/astar.py` searches a four-connected occupancy grid with a Manhattan heuristic. Static shelves, restricted cells, task constraints and known dynamic obstacles feed the planner. The engine validates complete graph reachability, station preconditions, inventory and capacity before authorization. Runtime guards remain mandatory for every movement and cargo transition.

`simulation/engine.py` owns pose, heading, velocity, cargo, inventory, action state, events and verification. Unexpected sensor occupancy invalidates routes; failure to find a route stops the mission. Missions have a 300-second simulated timeout. Pause preserves state; stop never grants verification. Verification requires final station, exact delivery counts, complete action sequence and collision invariants. Grid dimensions are 20 × 16 with 1m cells. The model does not represent contact mechanics or real robot actuation.

`evidence/reconcile.py` groups normalized cell claims. A fresh blocked sensor observation overrides a stale clear fixture claim; unresolved contradictory occupancy is blocked conservatively. Records retain observed/retrieved timestamps, IDs, reliability metadata, mission and provenance. Reliability numbers are configured metadata, not learned probabilities.

SQLAlchemy/SQLite persists terminal missions, experiments, retained parameter candidates and verified memory. Only verified outcomes enter memory. Retrieval checks environment, scenario, validity and a 24-hour freshness window; obstacle claims are revalidated against current authoritative state. Invalidated or stale outcomes remain auditable but cannot authorize actions. Memory is local PRAXIS functionality, not a Meterless Engine integration.

`experiments/runner.py` runs identical seeded task sequences across static, reactive and proactive evidence-informed policies. A speed candidate (2.4m/s vs 1.6m/s) is retained only when all trials verify, collisions remain zero, success does not regress and mean simulation time decreases. Timings include simulated task duration and actual planner decision/wall latency. Retained candidates persist with their experiment scope and can be applied explicitly. This is parameter evaluation, not neural training.

The `DomainAdapter` protocol separates warehouse data from planners for future domain implementations. Warehouse is the only operational domain. Integration activation is deliberately blocked pending verified external contracts; the diagnostics module is not an API adapter and never claims sponsor access.
